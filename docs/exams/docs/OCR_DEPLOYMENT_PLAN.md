# 本地 OCR 部署计划（2026-11-02）

用户已确定并授权部署以下方案，部署验收后恢复转录：

- 首选 Xiaomi-OCR-0；使用官方原始 checkpoint 与 Transformers 的 Apple Silicon 路径。
- 复杂文档、公式以 PaddleOCR-VL-1.6 作独立候选交叉核对。
- 批量 PDF 以 MinerU 处理；保留逐页来源定位。

实施选择：沿用项目 Python 命令行、来源清单和页级候选 IR。每个引擎独立虚拟环境，模型、原始结果和缓存置于忽略目录 `.work/ocr-local/`。避免常驻多模型服务；逐引擎串行推理，使 16 GB M3 的内存占用可控。官方模型、依赖版本、权重指纹、执行参数及实际运行证据均记录。采用原始权重优先于社区量化包，代价是更大下载量和运行内存。

接入边界：任何引擎结果都保持 `recognized_unverified` / `needs-review` / `not_verified`；不给整页结果猜题号，不自动覆盖规范 Markdown，不声称两个引擎一致即完成核验。来源 PDF 哈希、source ID、页码、渲染与输出指纹必须可追溯。原生 PDF 文字层优先复用；显式选页时允许重识别。

阶段与完成条件：

1. 核实官方部署接口，固定安装、下载与重建命令；逐模型下载并核验本机真实单样本推理。
2. 接入统一单图、PDF、批处理入口与交叉验证；对接既有 `ocr_candidate_ir.convert_run`；缓存验证绑定模型、参数、输入和输出内容。
3. 运行针对性回归与真实端到端验收，提交部署清单和操作说明。下载/依赖就绪与推理成功分别记录，失败不得标成功。
4. 核对 Git 与项目进度后选取下一份固定来源，继续转录；各阶段独立提交。

大模型推理错峰执行。依赖/网络失败优先按原始报错定位，不改用远程付费 OCR，不将真实来源或数学疑点补写成确定事实。
