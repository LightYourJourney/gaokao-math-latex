## 1. 背景与现状

上游仓库以 PDF 为主要载体，没有可直接复用的结构化题库、LaTeX 源文件或完整逐题解析。设计基线下共登记 775 份 PDF，其中 `普通高考/` 734 份、`春季高考/` 41 份。部分 PDF 有可用文本层，部分是扫描件；由 DOCX 转换的旧文件还可能存在公式显示缺陷。因此，PDF 文本提取、OCR 和模型识别只能生成初稿，最终题面必须逐页对照原 PDF。

本仓库并非空白起点。`math-gaokao-latex/` 已有 21 套独立试卷项目和 84 个四版本目标，公共层、生成脚本和版式约定已经形成。后续不再创建根级 `math-gaokao-latex/`，也不复制既有 21 套；全部新工作沿用现有规范路径，以避免两套工程相互漂移。

现有成果的基线是：2017–2026 已有 21 套项目；上游该年代段仍有大量全国卷、地方卷和春季卷未处理。历史日志中曾声称批次 2 有两套完成，但相关文件未提交并已丢失，故当前完成度只按磁盘文件、`index.json`、构建日志和 Git 提交机械计算，不采用 append-only 进度日志中的瞬时数字。

## 2. 核心决策与不变量

### 2.1 唯一工程根目录

规范路径固定为：

```text
math-gaokao-latex/
```

不迁移、不复制现有 21 套，不建立兼容符号链接。用户原始要求中的公共导言、宏、编译入口和每卷四版本，映射到现有 `common/`、`tools/`、`compile.sh` 与试卷子目录结构。

### 2.2 按独立题面去重

上游每个 PDF 都进入来源总账，但相同独立题面只建立一个项目。完全相同的 PDF 可依据 Git blob OID 和 SHA-256 自动归并；文件不同但疑似同卷时，必须比较题目数量、首尾题面和至少三道中间题，确认逐题内容一致后才可标记为语义重复。

地区标签、原始文件名、载体差异和适用范围作为别名保留，不通过复制工程表达。

### 2.3 答案使用外部来源与双重核验

当原 PDF 不含答案或解析时：

1. 优先使用考试院、原卷附带答案、权威出版物或可追溯的可靠题库；
2. 外部来源不足时，由一个代理独立求解，另一个代理盲核；
3. 两者冲突时启动第三次裁决，不能按多数投票直接通过；
4. 仍无法确认的题目标记为 `U`，对应试卷保持阻塞；
5. 自行推导的解析必须标明为项目独立整理，不得声称是官方标准答案。

### 2.4 小批端到端生产

每批默认 2–4 套，扫描质量差、图形多或答案来源困难时降为 1–2 套。每套从来源物化一路做到共享内容、四版本、编译、审计、报告和提交。禁止先制造数百套长期半成品，也禁止再次启动 14 个或更多并发转录任务。

### 2.5 阻塞不等于完成

图形待补、题面字符存疑、答案证据不足、编译失败或版式警告未裁决时，项目可以保留经过核验的中间成果，但状态必须为 `blocked`，不得计入完整试卷数。

### 2.6 二进制与临时产物不入库

`gaokaomath-src/`、上游 PDF、DOCX、页面渲染图、OCR 临时文件、编译 PDF、`.aux`、`.log` 和 `.out` 都是可重建产物，不提交 Git。永久保存的是来源身份、哈希、生成源、LaTeX 源、问题记录、验收报告和提交历史。

人工审核内容按字段划分为三份唯一规范源，现有“含解析”继续作为面向读者的生成文档：

```text
年份/规范卷名_试题.md       # 唯一拥有题面、题号、原卷说明
年份/规范卷名_答案要点.md   # 唯一拥有逐题最终答案
年份/规范卷名_解析正文.md   # 唯一拥有详细推导，通过稳定题号引用最终答案
年份/规范卷名_含解析.md     # 生成展示：题面 + 最终答案 + 详细推导
```

这样保留既有对外三件套（试题、答案要点、含解析），同时消除重复事实源。阶段 0 从现有 21 套的 `_含解析.md` 提取并人工抽验 `_解析正文.md`；提取时删除独立的题面复述和显式最终答案块，只保留稳定题号与详细推导。随后生成器从 `_试题.md` 注入题面、从 `_答案要点.md` 注入全部题型的最终答案、从 `_解析正文.md` 注入详细推导，重建 `_含解析.md`。最终答案只有 `_答案要点.md` 一个可编辑事实源。

规范项目中的 `questions.tex`、`answers.tex`、`answers_short.tex` 和四个版本壳是受版本控制的生成结果，不作为日常人工修改入口。项目 `figures/` 是 TikZ 的唯一永久源：合并书和其他展示工程只能从这里引用或复制，旧的“从合并书反向覆盖独立项目图形”流程在阶段 0 退役。内容修正流程固定为：修改对应字段的唯一源，运行 manifest 驱动生成器，校验生成结果，确认无非预期漂移。

## 4. 来源总账与状态模型

### 4.1 `source-manifest.json`

来源总账覆盖设计基线 commit 下的全部 775 份 PDF，顶层包括：

```json
{
  "schema_version": 1,
  "upstream": {
    "url": "https://github.com/deekur/gaokaomath",
    "commit": "34c13a6cf632c0b69c95f89b9b923bbc4a08924d"
  },
  "sources": [],
  "papers": [],
  "batches": []
}
```

`inventory_generated_at` 等运行时间字段可以由工具写入，但不参与内容身份判断。

#### `sources`

每份上游 PDF 一条。来源生命周期、题面关系和别名是三个正交维度，不能塞入同一个互斥枚举：

- 稳定 `source_id`；
- 上游相对路径；
- Git blob OID；
- SHA-256；
- 文件大小和页数；
- 本次物化与 PDF 结构校验结果；
- 年份、考试类型、科类、地区和原始卷名；
- `source_state`；
- `paper_relation`；
- 可为空的 `paper_id`；
- 问题编号。

`source_state` 是互斥状态：

| 状态 | 含义 |
|---|---|
| `not_started` | 已登记但尚未物化或分类 |
| `ready` | 来源可读且已完成身份核对 |
| `blocked` | 来源损坏、不可读或身份暂时不能确认 |
| `non_paper` | 经核实不是需要转录的数学试卷题面 |

`paper_relation` 仅在身份已确认时填写：

| 关系 | 含义 |
|---|---|
| `canonical` | 独立题面的规范来源 |
| `exact_duplicate` | 与规范来源 Git blob 或文件字节完全相同 |
| `semantic_duplicate` | 文件不同，经逐题核对确认题面相同 |

身份未确认时，`paper_relation` 和 `paper_id` 都允许为 `null`。地区标签、原始文件名和其他称谓只写入对应 `paper.aliases`，不参与来源状态计数；因此同一来源不会同时被算作“别名”和“重复来源”。

#### `papers`

每个独立题面一条，记录：

- `paper_id` 与永久 `legacy_ids` 兼容映射；
- 年份和规范卷名；
- 普通/春季高考；
- 文科、理科或不分科；
- 适用地区和别名；
- 所有 `source_id`；
- 项目目录；
- 三份字段规范源（试题、答案要点、解析正文）及生成展示文档（含解析）的显式 `source_files` 路径；
- 题目数、题型分段、图形数；
- 题面、答案、简答、图形树和公共层哈希；
- 答案证据等级分布；
- 构建与视觉回执路径；
- 当前问题编号；
- 当前生产状态。

#### `batches`

每批记录批次 ID、试卷列表、开始与关闭时间、起止状态、编译统计、抽查结果和阻塞项。清单不保存“包含自身的 commit hash”，避免 Git 自引用循环；批次与提交的关联由 `git log -- <批次路径>` 动态解析，或由后续闭合提交在报告中写入已经存在的前一内容提交 `artifact_commit`。

工具必须以稳定键排序和统一缩进写回 JSON，避免并行或重复执行造成无意义的大段 diff。阶段 0 必须先建立并验证 `source-manifest`、`provenance`、构建回执和视觉回执的 JSON Schema；只有 schema 校验通过的状态才可参与统计。

### 4.2 `index.json` 的边界

`source-manifest.json` 的 `papers` 是项目元数据的唯一事实源；现有 `index.json` 只覆盖已经进入规范 LaTeX 工程的项目，并由 manifest 投影生成。只有 manifest 投影工具有权整体写入 `index.json`。约束为：

```text
index.json 中每个 paper_id 必须存在于 source-manifest.json 的 papers 中
```

反向不要求成立。未开始或尚未生成规范项目的试卷可以只存在于总账。阶段 0 将现有 `index.json.id` 建立为永久 `legacy_ids` 映射，保留已有 `\gkpaperid`、标签和历史引用；旧 `split_project.py` 改为 manifest 驱动的兼容入口，支持按指定 `paper_id` 生成，且不得通过硬编码 21 套清单整体覆盖新项目或删除其他索引条目。

### 4.3 试卷生产状态机

```text
legacy_unverified                    # 仅用于现有 21 套迁移口径
planned
  → source_ready
  → transcription_draft
  → questions_verified
  → answers_draft
  → answers_verified
  → shared_frozen
  → editions_generated
  → compiled
  → complete
```

任何阶段都可以进入 `blocked`，但必须记录原状态、阻塞原因、关联问题编号、最后一个已验证哈希和明确恢复动作。报告汇总时：`planned` 计入 `not_started`；`source_ready` 至 `compiled`、`legacy_unverified` 计入 `in_progress`；`complete` 与 `blocked` 单独统计。只有身份已归并、已经存在于 `papers` 的对象参与独立题面守恒；尚不能分配 `paper_id` 的来源另计为 `identity_pending_sources`，不伪造“未开始试卷”。

Git 持久化是批次外层状态：工作树内容先从 `compiled` 经验证器派生为 `complete`，随后批次从 `validated` 进入 `committed`。Git 提交不属于单卷 `complete` 的内容条件。

### 4.4 完成定义

一套试卷只有同时满足以下条件才可标为 `complete`：

1. 来源已物化并登记身份、哈希和页数；
2. 题面逐页复核，题号、选项、公式和图形与原卷一致；
3. 每道答案有证据等级，并经过独立复核；
4. 年份级三份字段规范源与生成的“含解析”展示文档齐全；
5. `questions.tex`、`answers.tex`、`answers_short.tex` 和 schema 合法的 `provenance.json` 齐全；
6. `figure_count == 0` 时允许没有 `figures/`；`figure_count > 0` 时，manifest 登记的每个 TikZ 图形均存在、可编译并被引用；
7. 四个版本壳齐全且装配关系正确；
8. `receipts/build.json` 的输入树哈希与当前题面、答案、图形、公共层和模板完全一致，且四版本本轮 XeLaTeX 均成功；
9. 构建回执显示无 error、缺字和未解析引用；
10. Overfull 为零，或在构建与视觉回执中有逐项检查和豁免理由；
11. `receipts/review.json` 记录规定页面的视觉检查且输入哈希仍匹配；
12. 来源一致性、结构校验和批次报告均已完成。

`complete` 由验证器根据当前输入哈希、结构化回执和问题状态派生，不能由代理或人工直接写成 `true`。提交发生在验证之后，不形成完成条件的循环依赖。

## 5. 来源获取与全量抓取

“全部抓取”定义为：上游文件树可完整枚举；775 个 PDF 路径全部入总账；每个 blob 至少成功物化一次；SHA-256、大小、页数和 PDF 结构校验结果已记录；失败项有明确问题记录；本地来源可以重新生成页面渲染和文本提取材料。

当前 `gaokaomath-src/` 是 `blob:none` partial clone，设计基线下任务所需的部分 PDF 已物化。阶段 0 采用以下顺序补齐：

1. 固定并核对上游 commit；
2. 枚举 Git 树并生成来源清单；
3. 低并发批量物化缺失 PDF；
4. 单项失败时降低并发重试；
5. Git 对象获取持续失败时，按单文件或 codeload ZIP 降级；
6. 镜像只作为传输通道，下载结果必须用 blob 身份或 SHA-256 校验；
7. 每个 PDF 用文件头、解析工具和页数进行结构检查；
8. 不把“当前机器已物化”当作永久事实，只把身份、哈希和重建方法提交入库。

新机器重建时按固定 commit 获取来源，并对照总账验证，不依赖当前 `.git` 对象缓存。

## 6. 单批次端到端数据流

每批建立稳定批次 ID，例如 `2026-08-batch-001`，并在转录前冻结试卷清单。标准流程为：

```text
来源物化
  → 身份与重复性核对
  → PDF 页面渲染和文本提取
  → 逐页题面转录
  → 第二代理对照原卷复核
  → 答案证据搜集或独立求解
  → 第二代理盲核答案
  → 主代理裁决冲突并整合年份级字段规范源
  → 生成共享 LaTeX 内容
  → 冻结内容哈希
  → 四版本并行生成
  → 每版本快速编译
  → 主代理清理后统一重编译
  → 结构、日志、视觉和来源终验
  → 更新清单、报告并提交
```

### 6.1 题面转录

转录代理可使用 `pdftotext`、OCR、页面高清渲染和已有可信草稿生成初稿，但最终必须逐页对照原 PDF。重点核对：

- 年份、科类、卷别、地区、考试时间和满分；
- 题号连续性和原卷异常编号；
- 选择题选项顺序；
- 上下标、根号范围、分式层级、向量、集合和区间；
- “至少”“至多”“充分”“必要”等限定词；
- 图形点名、刻度、虚实线和方向；
- 跨页处漏题或重复；
- 页眉页脚是否误入正文。

OCR 不确定字符不能靠语义猜测；无法确认时登记问题并阻断完成。

### 6.2 答案证据等级

| 等级 | 来源 | 规则 |
|---|---|---|
| A | 原卷附带答案、考试院或明确官方材料 | 可标明官方来源，仍需检查转录错误 |
| B | 权威出版物、正式教师用书或可靠题库原始解析 | 核对卷别、题号和最终答案 |
| C | 两份彼此独立的可靠外部解析一致 | 排除相互转载的同一文本 |
| D | 独立求解并由第二代理盲核 | 标明项目独立推导，不声称官方 |
| U | 证据不足、来源冲突或无法确认 | 不写成确定答案，试卷保持阻塞 |

外部来源必须保存可重新定位的 URL、书目信息、文件路径或页码，不能只保存搜索摘要。外部材料只有最终答案时，只能为最终结论提供证据；详细解析仍由项目独立撰写并核查。

### 6.3 冲突裁决

答案来源不一致时依次检查卷别/科类/地区混淆、重新独立求解、第三角色审查和原题条件。裁决结果连同冲突来源、推导差异和理由写入 `provenance.json`。无法收敛则标 `U`，不能以“多数网站相同”替代独立证据。

### 6.4 图形处理

优先级为：复用可靠 TikZ/PGF、从 PDF 矢量对象重建、依据题面人工重绘、最后才使用明确的可编译占位。占位必须显示“图形待补”、登记问题，并使试卷保持 `blocked`。

每个图形使用独立 `figures/*.tex`，只包含 `tikzpicture` 内容，不包含文档类、题号、答案或绝对路径。图形不得擅自补充原题没有的直角、平行、等长、精确坐标或比例关系。

## 7. Subagents 并行与写入隔离

### 7.1 并发纪律

- 同时活跃 subagent 最多 4 个；
- 内容阶段通常同时运行 2–3 个；
- 每批 2–4 套，疑难批 1–2 套；
- 禁止 subagent 再创建 subagent；
- 共享内容冻结、确定性生成器产出四个壳文件后，才启动四个版本验收代理；
- 四版本验收代理处理当前批次，不一次处理全部历史试卷。

### 7.2 角色

- **主代理**：冻结批次、决定去重、整合规范内容、维护公共层和清单、终验并提交；
- **来源清点代理**：只读分析路径、元数据、哈希和重复候选；
- **题面转录代理**：每人一套，生成题面初稿、页码映射和疑点清单；
- **题面复核代理**：对照 PDF 输出差异，不直接覆盖规范内容；
- **答案求解代理**：搜集证据并独立求解；
- **答案复核代理**：在不查看第一份最终结论的前提下盲核；
- **图形代理**：生成 TikZ 初稿并列出可确认和不可确认元素；
- **四版本验收代理**：共享内容冻结且生成器完成后，分别编译、检查并报告当前批次的一种版本，不编辑确定性生成文件。

内容代理草稿写入被忽略的：

```text
math-gaokao-latex/.work/批次ID/试卷ID/
```

`.work/` 不是完成证据，不提交 Git。主代理把核验后的结果整合进年份级字段规范源，再由生成器写入“含解析”展示文档和规范项目。

### 7.3 四版本生成与验收所有权

四个壳文件是模板和 manifest 的确定性产物，只由同一个生成器一次生成当前批次四版本。模板只能由主流程或单一模板维护任务修改，版本验收代理不得编辑模板或生成壳。

| 代理 | 唯一职责与可写临时结果 |
|---|---|
| 试题版验收代理 | 在 `.work/` 隔离目录编译本批试题版，输出临时检查 JSON |
| 解析版验收代理 | 在 `.work/` 隔离目录编译本批解析版，输出临时检查 JSON |
| 简答版验收代理 | 在 `.work/` 隔离目录编译本批简答版，输出临时检查 JSON |
| 印刷版验收代理 | 在 `.work/` 隔离目录编译本批印刷版，输出临时检查 JSON |

四个代理均禁止修改规范源和正式回执，包括模板、版本壳、`questions.tex`、`answers.tex`、`answers_short.tex`、`figures/`、`provenance.json`、`receipts/`、`common/`、`index.json`、`source-manifest.json`、问题总账和报告。各代理只写 `.work/<batch>/<paper>/<edition>.json`，不得读改写同一份正式 JSON。发现母版或模板错误时只报告路径、题号和建议，由主代理修复、重新冻结并运行生成器。并行的价值放在快速编译和视觉审查，不在重复编辑确定性壳文件。

代理快速检查结束后，主代理必须清理规范 `build/` 并统一重编译当前批次四版本；只有这次串行收敛步骤有权一次性原子生成正式 `receipts/build.json`。临时 JSON 只作为诊断输入，不参与 `complete` 派生。

### 7.4 共享冻结

启动版本代理前记录：

```text
questions_sha256
answers_sha256
answers_short_sha256
figures_tree_sha256
common_tree_sha256
```

版本代理完成后重新计算。任一共享哈希变化即判本轮版本结果过期，重新冻结并重新生成四版本。派发后若主代理必须修改母版，同样将四版本全部标为过期，并把新增修改点加入终验锚点矩阵。

### 7.5 失败恢复

- 503 时不批量立即重试，先把并发从 4 降到 2，再降到 1；
- 只重试失败角色，不推倒已验证的独立成果；
- 中断的 `.work/` 草稿不自动合并；
- 结构性文件不完整时整份重做，不拼接半个新结构；
- 越权修改以实际 `git diff` 为准，撤销允许范围外的改动并重验共享哈希；
- 恢复时检查状态、实际文件、哈希、最近提交和问题记录，不依赖代理自述。

## 8. LaTeX 公共架构与内容规范

### 8.1 保留现有公共层

继续使用：

```text
common/preamble.tex
common/macros.tex
common/questions_env.tex
```

职责分别是宏包/版面、题号/答案/结构宏、机器可数语义环境。新增宏必须向后兼容；破坏性重命名需先加兼容别名、迁移全部调用并回归既有 84 个目标。

### 8.2 共享内容

`questions.tex` 只含忠实题面；`answers.tex` 与题目一一对应，含最终答案和详细解析；`answers_short.tex` 只含答案速查；`provenance.json` 保存来源与逐题核验，不参与排版。

每题保留一个 `question` 环境和 `\gkti{题号}`；每份详细答案保留一个 `answer` 环境和 `\gksolhead{题号}{答案摘要}`。稳定题目身份由 `paper_id + 原卷题号` 构成；小问使用 `.1`、`.2` 等来源映射，但不擅自改变原卷可见编号。

### 8.3 数学与题型

- 行内短公式用 `$...$`，独立公式用 `\[...\]`，多行推导用 `align*`、`aligned` 或 `gather*`；
- 不用 Unicode 数学字符替代标准 LaTeX 命令；
- 选择题继续使用 `gkopts`，依据内容选择 4、2 或 1 列；
- 不假设旧卷符合现代题型，原样保留判断题、作图题、计算题、证明题、选做题及原计分说明；
- 不为美化改变题面表达、单位、边界、限定词或选项顺序。

### 8.4 四版本装配

| 版本 | 输入关系 | 版式 |
|---|---|---|
| 试题版 | `questions` | A4、小四号、普通边距，只含题目 |
| 解析版 | `questions` → 换页 → `answers` | 题目加详细解析，保留题目页回链 |
| 简答版 | `questions` → 换页 → `answers_short` | 完整题目加答案速查，不加载详细解析 |
| 印刷版 | `questions` → `answers` | 五号字、窄边距、紧凑但可读 |

印刷版采用紧凑单栏为默认、局部双栏为优化。长公式、表格和大图保持单栏。不得通过不可读字号、整页缩放或图形过度压缩换取页数。

四个壳文件继续由生成器产生。模板从 Python 大字符串拆为四个 `.tex.tpl`，生成器支持按试卷、按版本和全量生成，不新增 Jinja 等外部依赖。

## 9. 构建与验收

### 9.1 构建目录与入口

编译产物统一进入每卷 `build/`。保留：

```bash
./compile.sh
./compile.sh 2021_新高考Ⅱ卷
./compile.sh 2021_新高考Ⅱ卷 解析版
```

新增：

```bash
./compile_all.sh
```

`compile_all.sh` 只是全量模式稳定包装，不复制第二套编译实现。

### 9.2 单目标编译

每个目标执行：

1. 删除该目标旧 PDF、日志和辅助文件；
2. 使用 `xelatex -interaction=nonstopmode -halt-on-error -file-line-error -no-shell-escape -recorder -output-directory=build` 编译；
3. 运行两遍并逐次检查退出码；
4. 验证 PDF 是本轮新生成；
5. 使用 `pdfinfo` 验证结构；
6. 扫描日志并输出页数和警告摘要；
7. 从 `.fls` 的 `INPUT` 记录提取仓库内实际读取文件，解析为规范仓库相对路径，去重排序并计算依赖闭包哈希；四个生成壳和生成器源码必须出现在闭包或独立哈希字段中；
8. 版本代理快速编译只写各自 `.work/` 临时 JSON；主代理统一四版本编译后才一次性原子写入正式 `receipts/build.json`，任何目标失败时正式回执必须明确记录失败且不得保留旧成功状态；
9. 单个失败时继续检查其余目标，但脚本最终返回非零。

### 9.3 硬失败与警告

以下任一出现即失败：XeLaTeX 非零退出、PDF 缺失、`^!`、Fatal error、Emergency stop、Missing character、未解析引用、未解析 citation、输入文件缺失或 `pdfinfo` 失败。

Overfull 默认失败。只有记录试卷、版本、源文件/行号、溢出宽度、视觉结果和接受理由后才可豁免。Underfull 默认警告，但若产生明显空洞或错位，视觉审查可升级为版式问题。

### 9.4 结构校验

每卷检查：

- `question` 数等于登记题数；
- `answer` 数等于登记题数；
- `\gkti` 与 `\gksolhead` 题号集合一致；
- 简答覆盖全部题目；
- 图形引用全部存在；
- 不含绝对路径、`.work/` 路径或最终 PNG/JPEG 题图；
- 四版本输入矩阵正确；
- 生成器重跑无意外漂移；
- 新增的人类说明性注释使用中文；TeX magic comment、命令名、标准字段和第三方原样片段不受此语言门禁约束。

四版本输入矩阵固定为：试题版只加载题目；解析版加载题目和详细答案；简答版加载题目和简答；印刷版加载题目和详细答案。

### 9.5 视觉验收

每批每套至少检查：四版本首页、一个题面密集页、所有图形页、解析起始页、简答页、印刷版候选拥挤页和最后一页。候选拥挤页由工具按页面文本字符数、公式对象数和图形覆盖率归一化后排序，取最高分页面；若人工改选，必须在视觉回执记录原候选、改选页和理由。检查字形、标题、题号、选项对齐、图形标注、页眉页脚、分页、字号、空白页、重复页和答案泄漏。

### 9.6 公共层回归

任何 `common/`、模板或生成器改动先检查代表性样板，再重新生成并编译现有 21 套 × 4 版本。只有 84 个目标全量回归通过，公共改动才能用于新批次。

## 10. 可提交验收回执

原始编译日志和渲染页面仍不提交，但完成状态所依赖的摘要证据必须可跨会话验证。

### 10.1 `provenance.json`

逐题记录：稳定题目 ID、来源 `source_id`、来源 SHA-256、PDF 页码、题面复核角色与结果、答案证据等级、证据定位、独立求解/复核角色、冲突状态、关联问题编号和最后核验时间。题面、来源或答案任一哈希变化时，对应逐题核验失效。

### 10.2 `receipts/build.json`

记录：

- 当前 `questions`、`answers`、`answers_short`、`figures`、`common`、四模板、四个生成壳和壳生成器源码的哈希；
- 依据 XeLaTeX `-recorder` 产生的 `.fls`，对仓库内实际读取文件规范化、排序后得到的完整依赖闭包清单与树哈希；
- XeLaTeX 与关键工具版本；
- 每个目标的完整参数数组、两遍退出码、PDF 页数和 PDF SHA-256；
- error、Missing character、未解析引用、Overfull、Underfull 摘要；
- 原始日志 SHA-256；
- 生成时间。

构建 PDF 和日志被清理后，回执仍能证明哪一组实际编译输入曾通过哪一版工具；但依赖闭包、生成壳、生成器源码或工具版本任一改变后，验证器必须把构建与视觉回执同时判为 stale 并要求重编译。正式回执只由主代理统一四版本编译步骤写入；并行版本代理无写权限。

### 10.3 `receipts/review.json`

记录与构建回执相同的输入树哈希、实际检查的版本和页码、检查项、审查角色、结果、Overfull 豁免理由和生成时间。视觉回执不保存截图本体；需要复核时按 PDF SHA-256 和页码重新渲染。

三个回执都必须通过 `schemas/` 中对应 JSON Schema。Markdown 报告只能渲染结构化回执，不能用自然语言“已检查”覆盖失败或缺失字段。

## 13. 质量抽查与报告

### 13.1 抽查

每批机械检查全部项目并进行规定页面的视觉审查。每完成一个年代阶段，按 `paper_id` Unicode 码点升序形成候选列表，再以 SHA-256 摘要 `gaokao-latex-audit-v1:<paper_id>` 的十六进制整数升序选择样本；这是一种固定、无运行时随机状态的可复现抽样。阶段不足 5 套则全部检查，否则至少检查 5 套。每套至少对照原 PDF 检查 2 道选择题、1 道填空题、1 道解答题和至少 1 道含图题；某题型不存在时在回执中记为“不适用”，不得用别的题型凑数。

最终分层抽查数量为：

```text
max(5, ceil(完成项目数 × 0.02))
```

抽样需覆盖 1950–2020 各年代、普通/春季高考、不同科类、文本/扫描 PDF、无图/图形密集卷。另设重点检查集，覆盖曾有 OCR 疑点、答案冲突、图形重绘、特殊宏、Overfull、回忆版或历史 transcript 恢复的卷。随机抽查和重点检查分别统计。

### 13.2 报告体系

- `docs/source-inventory.md`：上游 commit、目录、格式、数量、物化策略、限制和重建方法；
- `report.md`：全局来源、独立题面、完成/阻塞/未开始、版本编译、证据等级、图形、问题、抽查和网络情况；
- `math-gaokao-latex/reports/baseline.md`：阶段 0 基线；
- `math-gaokao-latex/reports/批次ID.md`：每批来源、题量、图形、证据、编译矩阵、视觉抽查、阻塞项和提交；
- `missing-issues.md`：当前与历史问题总账。

批次报告提交后不改写历史；后续修正通过新批次报告引用旧记录。

所有数字由工具根据 `source-manifest.json`、`index.json`、项目目录、`provenance.json`、构建/视觉回执和问题总账计算。原始构建日志只用于当次生成回执，不作为跨会话统计源。禁止手工维护相互独立的快照数字。

守恒关系为：

```text
来源总数
= source_state.ready + source_state.non_paper
+ source_state.blocked + source_state.not_started

source_state.ready
= paper_relation.canonical
+ paper_relation.exact_duplicate
+ paper_relation.semantic_duplicate

身份已归并的独立题面总数
= paper_status.complete + paper_status.blocked
+ paper_status.in_progress + paper_status.not_started

identity_pending_sources
= paper_id 为 null 且 source_state 不是 non_paper 的来源数
```

地区和原始命名别名不参与来源守恒计数。`paper_status.in_progress` 与 `paper_status.not_started` 按第 4.3 节的状态映射派生，不作为另一套可手工写入的状态枚举。

四个版本成功数分别统计，不以目录存在或旧 PDF 存在代替成功构建。

## 14. 提交、跨会话恢复与汇报

### 14.1 两级提交

一套试卷达到 `shared_frozen` 后，立即提交年份级字段规范源、生成的“含解析”展示文档、共享 LaTeX、图形、来源记录和对应状态，避免再次丢失未跟踪成果。

批次四版本、编译和终验完成后，再提交版本壳、索引、总账、问题记录、报告和必要工具更新。

每次提交前检查 `git status --short`，精确暂存当前批次路径，审查 staged diff，不使用 `git add .`，不夹带其他会话改动，不 push。

### 14.2 恢复协议

新会话按以下顺序恢复：

1. 读取 `CLAUDE.md` 和 `AGENTS.md`；
2. 检查 Git 状态和当前分支；
3. 读取来源总账；
4. 读取最近批次报告；
5. 验证最近提交和清单哈希；
6. 识别其他会话未提交改动；
7. 从最早未关闭状态继续。

不以 `/tmp`、代理自然语言自述或对话记忆作为唯一恢复依据。接近会话限制时不再开启新试卷，而是完成当前最小原子阶段、提交已验证内容、登记问题并输出恢复点。

### 14.3 进度汇报

在阶段开始、来源物化、每轮代理返回、共享内容冻结、四版本生成、编译完成、提交完成以及连续 503/来源冲突时汇报。每次汇报包含本批目标、完成试卷、共享提交、四版本提交、编译结果、阻塞项、累计覆盖和下一恢复点。

整个工程只有同时满足以下条件才可宣布完成：

1. 基线 commit 下 775 个 PDF 全部进入来源总账；

6. 全部题号、详细答案和简答映射通过；
7. 所有答案证据可追溯，provenance schema 校验通过；
8. 所有完整项目具有与当前输入匹配的视觉回执；
9. 所有未解决问题均进入总账和最终报告；
10. 随机与重点抽查完成；

## 17. 明确不做

| 不做 | 理由 |
|---|---|
| 创建第二个根级 LaTeX 工程 | 已确认沿用现有规范路径，避免双真相源 |
| 每个 PDF 无条件建一个重复项目 | 已确认按独立题面去重 |
| 一次启动数十或数百个代理 | 已发生 14/14 503，且无法安全恢复 |
| OCR 或模型初稿直接入库 | 可编译不等于内容正确 |
| 猜写不可辨认题面或无证据答案 | 违反忠实性与事实核查边界 |
| 默认全局双栏印刷版 | 长公式、表格和图形在窄栏中不稳定 |
| 提交来源和构建二进制 | 可重建、难 diff、会显著膨胀仓库 |
| 用旧 PDF 判断本轮编译成功 | 会产生假绿 |
| 依赖代理自报完成数 | 以文件、哈希、日志、清单和 Git diff 终裁 |
| 直接 push | 本仓库由既有每周流程统一 push |
