# 高考数学 LaTeX 工程阶段 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 打通「从上游 PDF 新建一套试卷」的完整链路，并用批次 7（`2021_全国甲卷_文科`、`2023_全国甲卷_文科`）端到端验证。阶段 0 只迁移了既有 21 套，本阶段补上缺失的注册能力与转录工作流，使后续 2–6 阶段可以批量复用。

**Architecture:** 沿用阶段 0 契约不变：`source-manifest.json` 是唯一事实源，`provenance.json` 逐题存证，四版本 LaTeX 由 manifest 确定性生成，构建/视觉回执 + 批次报告构成关闭门禁。本阶段新增的唯一写入口是 `source_manifest.py register-papers`，把「未绑定来源 → paper 记录 + batch 记录」这一步纳入既有 `state` 事务，不新建第二条状态通路。

**关键工序次序（由既有不变量倒推，不可调换）：**

```text
转录规范 Markdown → register-papers → init-batch → 填三角色 → import-batch → build → review → finalize
```

注册是对**已存在产物**的事实登记，不是占位：`_paper_record()`（`source_manifest.py:2115-2119`）要求四个规范 Markdown 在登记时已在盘上，`question_count` 与 `figure_files` 均须由真实 Markdown 数出（`figure_files` 还要通过 `validate_figure_occurrences` 的引用次数精确校验）。因此转录先于注册；逐题 provenance 证据则在注册之后经 `init-batch`/`import-batch` 建立。

**Tech Stack:** 与阶段 0 相同（Python 3.9 标准库、Bash 3.2、Git、XeLaTeX/TeX Live 2026、Poppler、TikZ/PGF）。

**Approved Spec:** `docs/superpowers/specs/2026-08-04-高考数学真题全量LaTeX工程-design.md` 第 12 节「阶段 1：补齐 2017–2026」。

## 阶段 0 实测语料事实（本计划的设计前提）

以下数字由 2026-08-14 对固定 commit `34c13a6` 的 775 份 PDF 全量机械扫描得出（`pdftotext -layout`，每页字符密度判定），是阶段 1–6 排期的依据：

| 事实 | 数值 | 对计划的约束 |
|---|---|---|
| 上游来源总数 | 775（普通 734 + 春季 41） | 已绑定 20，**待转录 755** |
| 无文本层（每页 < 50 字符） | **88（11%）** | 必须 OCR 或人工转录；集中在 1977（47）、1990s（18）、1980s（12） || 文本充分（每页 ≥ 200 字符） | 687（89%） | 可走 `pdftotext` 抽取 + 人工校对 |
| 含显式答案章节（参考答案/评分标准） | **19（2%）** | — |
| 含弱答案迹象（≥3 处行首「解:/证明:/答:」） | 4 | — |
| **无任何答案迹象** | **664 / 687 可抽文本者（96%）** | 绝大多数试卷的答案与解析**没有上游来源** |

**由此确定的核心口径**：上游几乎只提供题面。但这**不**意味着新卷只能停在 `blocked`——本项目既定方法论是「独立解题 + 盲审复核」：`solver_role` 独立解出答案，另一个 `reviewer_role` 盲核，再与库内答案要点三方比对，一致则记 `answer_evidence.grade = "A"`，并在成品页首显式声明「由本库编写者独立推导，非官方标准答案，若与官方发布版本不一致以官方为准」。2023 新高考Ⅰ卷 22 题全为 `A`，13 套 `complete` 皆由此路径达成。

这条路径与「严禁编造」不冲突，区别在于**归属是否诚实标注、推导是否经独立复核**。真正必须记 `U` 并立问题的，是解不出、或独立复核对不上、或与官方印本存在实质冲突的题（如 2025 全国 1 卷的 sin²C／sin C 之争）。

阶段 0 那 8 套 `blocked` 的实际原因可佐证：五套卡在**图形缺陷**（三视图/四选项图/散点图被画布截断、缺六爻示意图），一套卡在库内答案要点的排除依据写错，一套卡在官方与上游印本冲突，一套卡在回忆版身份。**没有一套是因为「答案无上游来源」**。

### Task 1: 放开 `legacy_ids` 约束并为 `register-papers` 写 RED 测试

**Files:**
- Modify: `math-gaokao-latex/schemas/source-manifest.schema.json`

**Interfaces:**
- Produces: `source_manifest.register_papers(repo, manifest_path, spec, *, write=False)`
- CLI: `source_manifest.py register-papers --manifest PATH --spec PATH [--write]`

**Steps:**

- [ ] **Step 0: 放开 `legacy_ids` 的 `minItems`，同时保住真正的不变量**

schema 当前把 `legacy_ids` 定为 required 且 `minItems: 1`，这是为阶段 0 那 21 套迁移卷写的。新转录的试卷**没有** legacy ID，编造一个等于伪造历史身份。改为 `minItems: 0`，并在 `_validate_paper_semantics()` 补一条定向断言：`paper_id` 落在冻结的 `LEGACY_PAPERS` 集合内的卷，其 `legacy_ids` 必须与常量表逐字相等。这样放开的只是新卷，迁移卷的身份约束反而变成显式机检。

Expected: 既有 810 个测试仍全绿（21 套迁移卷的 `legacy_ids` 未变）。

- [ ] **Step 1: 冻结注册契约的失败测试**

至少覆盖：注册规格中的 `source_id` 必须存在且当前 `paper_id is None`（重复绑定必须拒绝）；`project_dir` 与 `paper_id` 不得与既有 21 套冲突；`paper_id` 须匹配 `^gk-[0-9]{4}-[a-z0-9-]+$`；`batch_id` 须匹配 `^phase[0-9]+-b[0-9]{2}$` 且未被占用；`question_count` 必须为正整数；`questions`/`answer_key`/`combined_rendered` 三个规范 Markdown 必须已在盘上（`solution_body` 按既有约定只登记路径）；`--write` 缺省时零写盘且 manifest 字节不变；`--write` 时 revision 恰好 +1 且 `sources[].paper_id`/`paper_relation` 与新 paper 记录在**同一事务**内一致更新；批次记录的 `paper_ids` 与新注册集合逐字相等。

Expected: 全部失败（函数尚不存在）。

- [ ] **Step 2: 实现 `register_papers` 并转绿**

复用 `build_projects.commit_state()` 与既有 `reconciled_manifest()`；新 paper 记录字段与阶段 0 的 21 套逐字段同构（`paper_id/title/year/track/project_dir/question_count/source_ids/source_files/figure_files/legacy_ids/legacy_source_files/issue_ids/production_state/blocked_from/resume_action/last_verified_hash`）。必须满足 `_validate_paper_semantics()` 的全部不变量：`source_files` 恰四键且路径唯一、`figure_files` 按 path 排序去重且位于 `{project_dir}/figures/` 下、`expected_occurrences` 为正整数、`batch_id` 唯一且每卷至多属一个批次。四个规范 Markdown 必须已在盘上（见「关键工序次序」）。

Expected: Task 1 测试全绿；`source_manifest.py validate --require-artifacts 775` 仍通过（来源总数不变，只是绑定关系变化）。

### Task 2: 转录批次 7 题面到规范 Markdown

**⚠️ 已核实的身份矛盾（转录前必读）**

2021 两份上游 PDF 的**内页标题与文件名不一致**，且是系统性的：

| 上游文件名 | 内页标题 |
|---|---|
| `2021全国甲文(云南,广西,贵州,西藏,四川).pdf` | 普通高等学校招生考试 **(全国卷 II 文)** |
| `2021全国甲理(…同上…).pdf` | 普通高等学校招生考试 **(全国卷 II 理)** |
| `2021全国乙文(河南,山西,…).pdf` | 普通高等学校招生考试 **(全国卷 I 文)** |
| `2021全国乙理(…同上…).pdf` | 普通高等学校招生考试 **(全国卷 I 理)** |

2023 年的四份则内页与文件名一致（甲↔全国甲卷、乙↔全国乙卷），说明这是上游在 2021 年沿用了过期模板头。

- **【结论】** 文件名与省份列表正确，内页「全国卷 II」标签错误。2021 年全国甲卷适用云南、四川、广西、贵州、西藏五省区，其前身是**全国Ⅲ卷**而非Ⅱ卷。
- **【来源】** 2026-08-14 定向联网核查，多来源一致（百度百科「全国统一高考试卷」词条、知乎「2021高考共几套试卷」等）。
- **【置信度】** 高（省份列表与甲卷沿革两条独立证据互相印证）。

**处置**：按 ISSUE-0002（`conflict_code: regions-vs-upstream-path`，`type: identity-ambiguous`）的先例，在 Task 4 的 provenance 导入事务中立一条问题，记录内页标签与文件名的分歧、上述核查证据与裁定依据。`register_papers` 有意不写问题总账（保持单一职责），因此**不得**在 Task 3 静默跳过这一步。转录时以文件名与省份列表为准命名，**但正文中的卷别字样必须忠实转录原件**，不得代上游「订正」——原件写什么就是什么，分歧记在总账里。

**Files:**
- Create: `math-gaokao-latex/2021_全国甲卷_文科/` 下四个规范 Markdown 与 `figures/`
- Create: `math-gaokao-latex/2023_全国甲卷_文科/` 同上

**Steps:**

- [ ] **Step 1: 逐题转录题面**

两份上游均为 2 页 A3、文本层完好（约 14–15k 字符）、**零答案内容**。以 `pdftotext -layout` 抽取为草稿，**必须逐题对照 PDF 原页核对**：草稿含全半角混排与公式退化（如 `x 3 + bx 2` 实为 $x^3+bx^2$），直接采用即为错。图形一律 TikZ/pgfplots 重绘，禁止位图；每个图的引用次数须与 `figure_files.expected_occurrences` 精确一致。

- [ ] **Step 2: 答案按「独立解题 + 盲审复核」建立**

两卷答案均无上游来源，按项目既定方法论处理：`solver_role` 独立解出、另一 `reviewer_role` 盲核、与库内答案要点三方比对，一致记 `grade = "A"`，成品页首显式声明非官方归属。**解不出、盲核对不上、或与官方印本冲突的题一律记 `U` 并立问题**，不得为凑覆盖率降低证据标准。这一步天然适合并行 subagent：解题与盲核必须由**不同**代理独立完成，否则「盲核」名存实亡。
